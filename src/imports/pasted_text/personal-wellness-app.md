Crea una aplicación web moderna de **salud y bienestar personal**, con una experiencia visual clara, profesional, confiable y fácil de usar.

### 1. Concepto general

La aplicación debe funcionar como un **asistente digital de salud y bienestar**, orientado a ayudar al usuario a organizar y comprender sus hábitos de salud, registrar información personal y recibir recomendaciones generales de bienestar.

El diseño debe transmitir:

* Confianza
* Seguridad
* Profesionalismo
* Claridad
* Cercanía
* Privacidad
* Simplicidad

No debe parecer una aplicación médica fría ni una aplicación fitness extrema. Debe sentirse como una plataforma integral de **bienestar personal y prevención**.

### 2. Estilo visual

Crear una interfaz moderna tipo SaaS/HealthTech.

Características:

* Diseño minimalista y limpio.
* Mucho espacio en blanco.
* Tipografía moderna y altamente legible.
* Tarjetas con bordes suaves.
* Iconografía simple y profesional.
* Microinteracciones discretas.
* Excelente jerarquía visual.
* Diseño responsive para desktop, tablet y móvil.
* Navegación sencilla.
* Evitar saturación de información.
* Utilizar colores asociados a salud, tranquilidad y confianza.
* Los colores deben utilizarse como indicadores visuales y no como decoración excesiva.

La interfaz debe transmitir una sensación similar a una combinación entre una plataforma de salud digital, un dashboard moderno y una aplicación de bienestar premium.

### 3. Pantalla principal / Dashboard

Crear un dashboard personalizado para cada usuario.

Mostrar:

**Resumen de hoy**

* Estado general de bienestar.
* Actividad física.
* Sueño.
* Hidratación.
* Alimentación.
* Estado de ánimo.
* Recordatorios importantes.

**Indicadores principales**

Crear tarjetas para:

* Peso y evolución.
* Presión arterial, si el usuario decide registrarla.
* Glucosa, si corresponde.
* Horas de sueño.
* Actividad física.
* Consumo de agua.
* Estado de ánimo.

Cada indicador debe mostrar:

* Valor actual.
* Evolución.
* Fecha de actualización.
* Gráfico sencillo.
* Tendencia positiva, estable o requiere atención.

No realizar diagnósticos médicos basándose únicamente en estos datos.

### 4. Perfil de salud

Crear una sección denominada **"Mi Salud"**.

Permitir al usuario registrar voluntariamente:

* Datos personales.
* Edad.
* Altura.
* Peso.
* Objetivos personales.
* Actividad física.
* Hábitos de sueño.
* Alimentación.
* Consumo de agua.
* Mediciones personales.
* Antecedentes relevantes que el usuario quiera registrar.
* Medicamentos o suplementos, únicamente como información personal y sin generar prescripciones.

Los datos sensibles deben estar claramente identificados y protegidos.

### 5. Objetivos

Crear un sistema de objetivos.

Ejemplos:

* Mejorar hábitos de sueño.
* Aumentar actividad física.
* Mejorar hidratación.
* Mantener una alimentación equilibrada.
* Registrar mediciones periódicamente.
* Mejorar bienestar general.

Cada objetivo debe tener:

* Meta.
* Progreso.
* Fecha de inicio.
* Fecha objetivo opcional.
* Historial.
* Indicador visual de progreso.

Evitar objetivos extremos relacionados con pérdida rápida de peso, restricción alimentaria o sobreentrenamiento.

### 6. Asistente de IA

Incorporar un **asistente virtual de bienestar basado en IA**.

El asistente debe permitir preguntas como:

* "¿Cómo puedo mejorar mi sueño?"
* "¿Qué hábitos puedo mejorar esta semana?"
* "¿Cómo puedo organizar mejor mi alimentación?"
* "¿Qué puedo hacer para mantenerme hidratado?"
* "¿Cómo puedo empezar a hacer más actividad física?"

La IA debe:

* Utilizar los datos proporcionados voluntariamente por el usuario.
* Explicar sus recomendaciones de forma sencilla.
* Mostrar el razonamiento general de sus recomendaciones cuando corresponda.
* Diferenciar claramente entre información general y atención médica profesional.
* No realizar diagnósticos.
* No prescribir medicamentos.
* No indicar cambios de dosis.
* No reemplazar a un médico u otro profesional sanitario.
* Recomendar consultar a un profesional cuando una situación pueda requerir evaluación clínica.

Mostrar una advertencia discreta pero visible:

**"Esta herramienta entrega información general de bienestar y no reemplaza la evaluación de un profesional de la salud."**

### 7. Registro diario

Crear una sección **"Mi día"** donde el usuario pueda registrar rápidamente:

* Agua.
* Actividad física.
* Sueño.
* Alimentación.
* Estado de ánimo.
* Notas personales.

El registro debe ser extremadamente rápido, idealmente mediante botones, sliders, selectores y controles simples.

### 8. Estadísticas

Crear una sección de análisis con gráficos.

Mostrar:

* Evolución semanal.
* Evolución mensual.
* Tendencias.
* Cumplimiento de objetivos.
* Comparación de períodos.
* Historial de mediciones.

Los gráficos deben ser simples y comprensibles para usuarios no técnicos.

### 9. Alertas y recordatorios

Crear un sistema de notificaciones para:

* Registrar mediciones.
* Beber agua.
* Registrar actividad.
* Revisar objetivos.
* Completar registros diarios.

Las notificaciones relacionadas con salud deben utilizar un lenguaje preventivo y no alarmista.

### 10. Privacidad y seguridad

La privacidad debe ser un elemento central de la aplicación.

Implementar:

* Autenticación segura.
* Control de acceso.
* Gestión de sesiones.
* Protección de datos sensibles.
* Cifrado cuando corresponda.
* Validación de entradas.
* Registro de actividad relevante.
* Principio de mínimo privilegio.
* Posibilidad de eliminar la cuenta.
* Posibilidad de eliminar los datos personales.
* Consentimiento explícito para el tratamiento de información sensible.
* Política de privacidad claramente visible.

No utilizar datos personales para funcionalidades de IA sin consentimiento apropiado.

### 11. Navegación

Crear un menú principal sencillo:

**Inicio**
**Mi Salud**
**Mis Objetivos**
**Mi Día**
**Estadísticas**
**Asistente IA**
**Perfil**

En móvil utilizar navegación inferior o un menú adaptativo.

### 12. Experiencia de usuario

La aplicación debe estar diseñada pensando en personas que no necesariamente tienen conocimientos médicos o tecnológicos.

Utilizar:

* Lenguaje sencillo.
* Explicaciones breves.
* Tooltips cuando sean necesarios.
* Mensajes de error claros.
* Estados vacíos útiles.
* Confirmaciones antes de acciones importantes.
* Formularios cortos.
* Acciones frecuentes accesibles desde el dashboard.

No mostrar información médica compleja sin contexto.

### 13. Onboarding

Crear un onboarding inicial de 4–5 pasos:

1. Bienvenida.
2. Información básica.
3. Objetivos personales.
4. Hábitos que desea registrar.
5. Configuración de recordatorios.

Al finalizar, generar un dashboard personalizado.

### 14. Arquitectura

Diseñar la aplicación con una arquitectura escalable y modular.

Separar:

* Frontend.
* Backend/API.
* Base de datos.
* Servicio de autenticación.
* Servicio de IA.
* Sistema de notificaciones.

Crear una API REST bien estructurada.

Utilizar variables de entorno para secretos y claves API.

Nunca exponer claves privadas de servicios de IA en el frontend.

### 15. Modelo de datos

Diseñar entidades/colecciones para:

* Users
* HealthProfiles
* HealthMeasurements
* DailyLogs
* Goals
* GoalProgress
* Notifications
* AIConversations
* AIRecommendations
* ConsentRecords
* AuditLogs

Utilizar timestamps y mantener historial cuando sea necesario.

### 16. Dashboard administrativo

Crear un panel administrativo independiente.

El administrador podrá:

* Gestionar usuarios.
* Revisar métricas generales de uso.
* Gestionar contenido de bienestar.
* Gestionar recomendaciones.
* Administrar categorías.
* Revisar logs técnicos.
* Gestionar configuraciones.

El administrador NO debe acceder automáticamente a información sensible del usuario. Implementar permisos y controles de acceso adecuados.

### 17. Diseño responsive

La aplicación debe funcionar correctamente en:

* Desktop.
* Tablet.
* Smartphone.

Diseñar primero pensando en una experiencia móvil clara y posteriormente adaptar el layout para pantallas grandes.

### 18. Accesibilidad

Cumplir buenas prácticas de accesibilidad:

* Contraste adecuado.
* Tamaños de texto legibles.
* Navegación mediante teclado.
* Labels correctos.
* Estados de foco.
* Mensajes de error comprensibles.
* No depender exclusivamente del color para comunicar estados.

### 19. Página de inicio

Crear una landing page moderna con:

**Hero**
"Cuida tu salud. Entiende tus hábitos. Mejora tu bienestar."

Subtítulo:
"Una plataforma inteligente para registrar, comprender y mejorar tus hábitos de salud de manera simple y segura."

CTA principal:

**"Comenzar ahora"**

CTA secundario:

**"Conocer la plataforma"**

Secciones:

* Cómo funciona.
* Beneficios.
* Asistente inteligente.
* Seguimiento de hábitos.
* Privacidad y seguridad.
* Preguntas frecuentes.

### 20. Principios fundamentales

La aplicación debe seguir estos principios:

**Simple:** cualquier usuario debe entenderla rápidamente.

**Confiable:** evitar afirmaciones médicas no fundamentadas.

**Segura:** tratar los datos de salud como información altamente sensible.

**Preventiva:** fomentar buenos hábitos sin generar alarmismo.

**Personalizada:** adaptar la experiencia según los objetivos del usuario.

**Transparente:** explicar claramente qué hace la IA y cuáles son sus limitaciones.

**Escalable:** preparar la arquitectura para futuras integraciones con wearables, APIs de salud, laboratorios y otros servicios.

### Resultado esperado

Crear un prototipo funcional y visualmente profesional de una plataforma HealthTech moderna.

Priorizar primero:

1. Landing page.
2. Registro/login.
3. Onboarding.
4. Dashboard.
5. Perfil de salud.
6. Registro diario.
7. Objetivos.
8. Estadísticas.
9. Asistente IA.
10. Privacidad y seguridad.

La interfaz debe sentirse como un producto real listo para evolucionar hacia una plataforma de salud y bienestar profesional, no como un simple formulario o dashboard genérico.
